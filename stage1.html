1. Executive Summary & Objective

TestPilot AI is an autonomous multi-agent web application testing platform designed to discover functional failures, performance bottlenecks, and concurrency flaws by simulating multiple realistic user personas interacting concurrently.

Core Problem Addressed

Features often pass unit tests in isolation but fail dramatically under concurrent real-world usage:

  • Two clients hiring the same freelancer when only 1 slot is available.
  • Duplicate order, booking, or payment submissions during double-clicks.
  • Silent message loss or state desynchronization under high load.
  • Database locking conflicts and performance degradation.

Core Objective

Accept a target application URL and feature descriptions, autonomously generate realistic personas and valid/edge-case workflows, and run hybrid deterministic tests:

  • Locust: High-throughput API-level virtual users (up to 500 VUs).
  • Playwright: Selected real browser sessions for visual & DOM assertions.
  • Evidence-Backed Root Cause: Verified defect reporting with logs & traces.

2. Scope & Target Boundaries

In Scope for Initial MVP

  • Submission of target URL and role descriptions
  • Configurable virtual-user load (10 to 500 VUs)
  • AI analysis of roles, endpoints, and business rules
  • Persona generation (Admin, Buyer, Seller, Edge user)
  • Workflow generator (happy path, edge cases, error cases)
  • Locust API simulation + Playwright real browser testing
  • Functional expected vs actual assertions
  • Concurrency validation & race-condition surface checks
  • HTML and PDF evidence report generation

Reserved for Future Releases

  • Advanced kernel-level race condition detection
  • Distributed multi-node load testing clusters
  • Advanced dynamic application security testing (DAST)
  • Automatic test environment cloud provisioning
  • Cross-run regression history diffing
  • Bidirectional GitHub issue / PR sync automation

3. Functional Requirements (FR-01 to FR-12)

ID Requirement Specification
FR-01 Project Submission Allow users to submit target URL, authentication context, and feature descriptions.
FR-02 Test Configuration Configure virtual users (10–500), duration, ramp-up rate, intensity, and pass/fail thresholds.
FR-03 Requirement Analysis AI parsing of user-provided features, roles, API endpoints, and expected business logic.
FR-04 Persona Generation Generate realistic behavioral personas with distinct attributes, speed, and goals.
FR-05 Workflow Generation Form deterministic action sequences and stateful user journeys based on personas.
FR-06 Concurrent Simulation Simulate multiple virtual users concurrently with realistic pacing and thinking time.
FR-07 Functional Validation Assert actual system responses against expected business invariants and error codes.
FR-08 Concurrency Validation Execute simultaneous actions against shared resources to detect double-booking or state corruptions.
FR-09 Performance Testing Measure p50, p95, p99 response times, requests per second (RPS), and error rates.
FR-10 Load Testing Modes Support load, stress, spike, and soak testing execution patterns.
FR-11 Failure Analysis Correlate failing requests, screenshots, and logs into evidence-backed root-cause explanations.
FR-12 Report Generation Produce structured HTML and downloadable PDF reports with executive and technical summaries.

4. Non-Functional Requirements (NFR-01 to NFR-11)

ID Pillar Quality Attribute Target
NFR-01 Performance FastAPI endpoints respond in <150ms; real-time dashboard updates smoothly.
NFR-02 Scalability Easily scale worker processes to sustain up to 500 API virtual users on benchmarked hardware.
NFR-03 Reliability Task queues (Celery/Redis) with state persistence so interrupted test runs can be cleanly recovered.
NFR-04 Security SSRF protection, target domain allowlisting, AES encryption for stored credentials.
NFR-05 Isolation Strict sandbox separation between concurrent project workspaces and test executions.
NFR-06 Accuracy No hallucinated bugs: every reported defect must be linked to a captured HTTP/DOM log or screenshot.
NFR-07 Usability Clean 3-step test setup: Provide URL → Pick Load Preset → Run & View Dashboard.
NFR-08 Maintainability Decoupled architecture: Testing engines (Locust/Playwright) remain swappable and modular.
NFR-09 Compatibility Standard HTTP/HTTPS, REST, GraphQL, and modern Single Page Applications (React, Vue, Next.js).
NFR-10 Observability Structured JSON logging, Prometheus metrics, Grafana dashboards for engine health.
NFR-11 Cost Efficiency Zero LLM calls during high-frequency Locust loops; LLMs are only used for upstream reasoning.

5. Multi-Agent & Technological Foundation

TestPilot AI leverages 7 specialized agent roles working alongside deterministic engines:

1. Requirement Analyzer
Extracts application roles, invariants, and functional boundaries from specs.
2. Application Explorer
Curls endpoints and maps live reachable DOM pathways.
3. Persona Generator
Constructs user profiles with specific roles, budgets, and habits.
4. Workflow Generator
Translates personas into executable step-by-step HTTP & browser actions.
5. Test Coordinator
Orchestrates Locust workers and Playwright browsers synchronously.
6. Result Analyzer
Parses status codes, response times, and failure traces into insights.
7. Report Generator
Compiles formatted Markdown, HTML, and PDF reports for stakeholders.
